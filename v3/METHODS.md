# Methods

## 1. Model overview

We study the evolutionary dynamics of a single asexual species on a spatially explicit lattice using an individual-based (agent-based) model. Each individual carries a fixed-length binary genome from which its heritable phenotype is deterministically derived, occupies a discrete cell of a two-dimensional toroidal grid, forages for a renewable resource, and is exposed to spatially distributed hazards ("pitfalls") whose lethality depends on the match between a heritable defense locus and the hazard's bit pattern. The central scientific question the framework is designed to address is whether a transient, environmentally triggered increase in the germline mutation rate ("stress-induced hypermutation") accelerates adaptation to a novel hazard relative to a constant low mutation rate, without incurring a demographic cost that drives the population to extinction. The model therefore couples explicit population demography (overlapping generations, senescence, density-dependent resource limitation) with population genetics (heritable quantitative and defensive traits, mutation, selection through differential survival and fecundity).

The model is formulated in discrete time. The fundamental time step is referred to as a *tick*; a fixed number of ticks constitutes a reporting *epoch* at which population-level observables are recorded. All stochastic processes are driven by a single pseudo-random number generator (PRNG) whose state is fully determined by an integer seed, rendering every simulation trajectory exactly reproducible given its configuration and seed.

## 2. Software implementation and design principles

The framework is implemented in Python (>=3.12) with a structure-of-arrays (SoA) memory layout: each state variable of the population is stored as a contiguous typed array indexed by individual, and the living population is maintained as a dense prefix of these arrays that is compacted upon death. This layout replaces per-object iteration with vectorized array operations and admits just-in-time compilation of the computational kernels. Three interchangeable numerical backends are provided for the hot-path kernels (drain, population-count, nearest-resource search, senescence curves): a pure NumPy backend (always available), a Numba (LLVM) just-in-time backend for the CPU, and an optional CUDA backend, with automatic fallback from CUDA to Numba to NumPy when hardware or drivers are absent. The simulation engine is strictly separated from all user-interface and analysis code, so that identical numerical results are obtained whether a run is executed headlessly, visualized interactively, or embedded in a batch experiment.

Determinism is a first-class property. Given an identical configuration (including the world seed) and an identical CPU backend (NumPy or Numba), the sequence of states produced by the engine is bit-for-bit reproducible. The CUDA backend may differ in the least significant bits owing to non-associative floating-point reductions and is therefore not used for reproducibility-critical comparisons.

## 3. Spatial environment and resource dynamics

Space is represented as a rectangular lattice of width W and height H cells with periodic (toroidal) boundary conditions, so that movement and perception wrap at the edges and no cell is privileged. Two resource fields are defined over the lattice: a food field and a hazard (pitfall) field. Each field is stored as a per-cell integer "lifespan" counter; a positive counter denotes the presence of a resource item with the corresponding remaining persistence, and the counter is decremented each tick until the item expires.

Food items are introduced stochastically each tick at an expected rate proportional to the parameter food_rate (items per tick, drawn so that the realized count is an integer close to the nominal rate), placed at uniformly random unoccupied positions, and assigned a fixed persistence of food_lifespan ticks. Hazard items are introduced analogously at rate pitfall_rate with persistence pitfall_lifespan ticks; each hazard item carries the 32-bit sequence of a *pitfall type* drawn from the currently active type set (see Section 11). At initialization, a standing crop of food equal to approximately half the steady-state carrying stock (food_rate x food_lifespan / 2) is seeded so that founders do not begin in a barren environment. Resource turnover (spawning and expiry) is the first phase executed on every tick, ensuring that perception, movement, and interaction within a tick operate on a consistently updated environment.

## 4. Individual state and genetic architecture

### 4.1 Genome representation

Each individual carries a haploid binary genome of L bits (default L = 2048), stored in packed form as an array of 32 unsigned 64-bit integers. Bit-packing allows mutation and trait extraction to be performed with vectorized bitwise operations and hardware population-count instructions rather than per-bit manipulation. The genome is partitioned into designated *coding regions* and non-coding ("junk") remainder. By default three coding regions are defined over bit indices [0,64), [64,128) and [128,160), from which four heritable traits are read: body weight (bits [0,32)), locomotor speed (bits [32,64)), reproductive age (bits [64,96)), and a defense locus (bits [128,160)). The remaining bits are selectively neutral and serve as a reservoir in which mutations accumulate without direct phenotypic effect.

### 4.2 Genotype-phenotype map

Quantitative traits are obtained by interpreting the relevant bit block as an unsigned integer under a binary (or, optionally, reflected Gray) encoding and normalizing to the unit interval; the normalized value is then affinely mapped onto the trait's admissible range. Body weight and speed are mapped onto configured limits and initialized within specified sub-ranges. The reproductive age is mapped from its 32-bit block onto the closed interval [repro_age_min, repro_age_max], so that an all-zero block yields the minimum and an all-one block the maximum permissible age of first reproduction. The defense locus is read directly as a 32-bit integer and compared bitwise against hazard sequences (Section 10). Because the map is deterministic, offspring phenotypes follow immediately from inherited (and possibly mutated) genotypes.

## 5. Scheduling: the synchronous update cycle

Within each tick the population is updated in a fixed sequence of synchronous phases; all individuals experience a given phase before any proceeds to the next, eliminating order-of-iteration artifacts inherent to asynchronous agent updates. The phases, in order, are:

1. Resource turnover: food and hazard items are spawned at their configured rates and all resource lifespan counters are decremented, expiring exhausted items.
2. Senescent mortality: individuals whose age has reached max_age are removed (age-related death).
3. Metabolic expenditure and starvation: each individual's energy reserve is decremented by its metabolic cost (Section 6); individuals whose energy reaches zero are removed (starvation).
4. Emergency mortality: individuals below a critical energy threshold (low_energy_death_threshold) that have no food item within their perceptual radius are removed. This check precedes movement, representing individuals that are simultaneously energy-depleted and unable to perceive a proximal resource.
5. Perception and movement: each individual moves with probability equal to the product of its speed and its age-dependent mobility (Section 7), clipped to [0,1]. A moving individual that perceives at least one food item within its eyesight radius steps one cell toward the nearest such item; otherwise it takes a single random step. Movement wraps toroidally.
6. Feeding: on each food-bearing cell at most one individual feeds, resolved by descending body weight with uniform random tie-breaking; the successful individual's energy increases by food_gain scaled by its age-dependent absorption efficiency, and the food item is consumed.
7. Hazard resolution: individuals co-located with a hazard item sustain damage determined by the mismatch between the hazard sequence and their defense locus (Section 10); the corresponding energy loss is applied and lethal encounters are recorded as hazard deaths. A subsequent starvation check removes any individual whose energy has been driven to zero.
8. Reproduction: individuals that have reached their genetically encoded reproductive age and have not previously reproduced produce a single clutch (Section 8).
9. Time advance and perturbation check: the global tick counter is incremented and the environmental perturbation controller is evaluated, which may trigger or terminate a stress episode (Section 11).
10. Reporting: at every metrics.interval ticks an optional density cull may be applied and the full suite of population-level observables (Section 12) is computed and recorded, defining one epoch.

## 6. Bioenergetics

Each individual holds a scalar energy reserve in [0,1]. Energy is expended every tick through a metabolic cost that comprises a fixed basal component and a locomotion-related component increasing with the product of body weight and speed, and (optionally) a cost proportional to the number of active defense bits. Formally, the per-tick expenditure takes the form base_metabolism + k_weight_speed x (weight x speed) (+ optional defense cost), and the reserve is decremented accordingly and clipped at zero. Energy is replenished only by feeding, with intake equal to food_gain modulated by the individual's age-dependent absorption efficiency (Section 7). This construction imposes an explicit life-history trade-off: high speed improves the probability of reaching perceived food but raises the metabolic burden, while body weight confers competitive priority at contested food cells at an energetic cost. Individuals whose reserve reaches zero die of starvation; the emergency-mortality rule additionally removes energy-depleted individuals that cannot perceive food, capturing acute resource failure prior to movement.

## 7. Senescence

Aging is modeled as a plateau followed by monotone decline in two physiological efficiencies: locomotor mobility and food-absorption efficiency. For age a, both efficiencies equal unity while a <= onset. For onset < a < max_age they decline along a normalized trajectory t = (a - onset)/(max_age - onset), either linearly (default) or quadratically (t -> t^2), from unity toward configured asymptotes mobility_end and absorption_end respectively; at a >= max_age the individual is removed by senescent mortality. Mobility enters the model multiplicatively in the movement probability (speed x mobility), so that senescent individuals move less reliably; absorption scales the energetic yield of feeding, so that senescent individuals extract less energy per food item. Because reproduction is scheduled within a fixed age window (Section 8) while senescence onset is configurable independently, the model admits late-reproducing individuals whose fertile period overlaps the onset of decline.

## 8. Reproduction and inheritance

Reproduction is per-individual and semelparous within the simulated horizon: each individual reproduces exactly once, at the unique tick at which its age equals its genetically encoded reproductive age, provided it has not already done so; a persistent flag prevents repeated clutches. The number of offspring is a step function of the parent's energy at that tick: individuals with energy below repro_energy_low produce no offspring (but are nonetheless marked as having reproduced), individuals with energy in [repro_energy_low, repro_energy_high) produce one offspring, and individuals with energy at or above repro_energy_high produce two. Reproduction is clonal: each offspring inherits a copy of the parental genome subject to mutation (Section 9). Parents are not replaced upon reproduction and continue to live until removed by starvation, emergency, hazard, or senescent mortality; generations therefore overlap. When a hard population ceiling (max_animals) is reached, additional births are suppressed and recorded as skipped, so that the resource supply, rather than an arbitrary cap, is the operative demographic regulator under normal conditions.

## 9. Mutation

Mutation acts on the inherited genome at fertilization. Each eligible bit is independently flipped with probability equal to the prevailing per-bit mutation rate. Under baseline (non-stress) conditions the rate equals base_mutation_rate and mutation is restricted to the coding regions; under an active stress episode the rate equals stress_mutation_rate and may optionally remain coding-restricted (stress_mode_coding_only). Restricting mutation to coding regions during the perturbation focuses genetic variation on phenotypically consequential loci, including the defense locus that determines hazard survival, and is the mechanistic locus of the hypermutation hypothesis: elevating stress_mutation_rate increases the per-generation supply of defense variants against a newly introduced hazard.

## 10. Environmental hazards and the adaptation metric

Each hazard item carries a 32-bit sequence in which set bits denote "dangerous" positions. An individual co-located with a hazard sustains damage equal to the number of dangerous bits not covered by its defense locus,

damage = popcount(seq AND (NOT defense)),

and loses energy in proportion to the fraction of the 32-bit motif that is damaging, scaled by the maximum per-encounter loss max_pitfall_loss_pct; encounters that reduce energy to zero are recorded as hazard deaths. To quantify defensive match independently of demographic outcome, we define, for each encounter, an adaptation score as the fraction of dangerous bits that the defense locus covers:

need = popcount(seq),  covered = popcount(seq AND defense),  score = covered / need  (score := 1 if need = 0).

Non-dangerous (zero) bits of the hazard are ignored, as they never inflict damage and thus constitute no adaptive target. The population-level adaptation score reported at each epoch is the mean of this per-encounter score over all encounters in the epoch, and the adapted fraction is the proportion of encounters that are fully covered (score = 1, equivalently zero damage). These two observables jointly summarize the degree and completeness of defensive adaptation to the prevailing hazard regime.

## 11. Environmental perturbation: the stress protocol

A controlled environmental perturbation models the appearance of a novel hazard together with the physiological stress response. The perturbation is scheduled at a configurable tick (stress.trigger_tick). Because the perturbation controller is evaluated immediately after the tick counter is incremented, the trigger tick must be greater than or equal to one; when a simulation is resumed from a saved state (Section 13), the trigger tick must exceed the tick of that saved state for the event to occur. Upon triggering, three coupled changes take effect. First, one or more novel hazard types (by default a single type, "B") are added to the active hazard set, and a burst of pitfall_burst_count hazard items of the novel type is spawned, so that the population is abruptly exposed to a hazard against which its standing defenses were not selected. Second, the world enters the stress state, in which the mutation rate switches from base_mutation_rate to stress_mutation_rate for the duration of the episode. Third, the food-input rate may optionally be modulated for the duration of the episode. If a finite duration (stress.duration_ticks) is specified, the stress state (and hence the elevated mutation rate) is terminated after that many ticks, while the newly introduced hazard type persists; otherwise the episode continues to the end of the run.

The default hazard sequences are constructed to maximize the adaptive challenge. The ancestral type "A" (motif 11110000 repeated four times) and the novel type "B" (motif 00001111 repeated four times) have disjoint sets of dangerous bit positions, each with sixteen dangerous bits. Consequently, a defense locus selected to cover type A confers no coverage against type B (covered = 0, score = 0 at the moment of introduction), so that adaptation to B must be acquired de novo through mutation and selection following the perturbation. This design isolates the rate of de novo adaptation as the quantity of interest and renders it maximally sensitive to the mutation-supply manipulation.

Because the introduction of the novel hazard and the elevation of the mutation rate are, by default, effected by the same trigger, the two manipulations can be experimentally decoupled where required: exposing a group to the novel hazard while holding its mutation rate at the baseline value is achieved by triggering the perturbation but setting stress_mutation_rate equal to base_mutation_rate for that group. This permits a clean contrast between adaptation under hypermutation and adaptation under a constant low mutation rate, both facing the identical environmental change.

## 12. Observables

At each epoch the following population-level observables are recorded: census size and the per-cause mortality counts (starvation, emergency, hazard, senescence, cull) and birth counts accumulated over the epoch; the mean, median, extrema, and standard deviation of the energy reserve; the mean body weight, speed, defense-bit count, reproductive age, and realized age (with median and maximum); the mean age-dependent mobility, absorption, and movement probability; genetic diversity, estimated as the mean pairwise Hamming distance over a random sample of genomes (sample size capped for tractability); the number of distinct defense sequences; food dynamics (spawned, consumed, expired, and standing availability); hazard-encounter count, mean damage, and the count of zero-damage encounters; the adaptation score and adapted fraction (Section 10); an indicator of whether the stress state is active; and the effective mutation rate in force. A cumulative adaptation trajectory is additionally maintained at fine temporal resolution to permit visualization of the approach to defensive coverage over time.

## 13. Experimental design: checkpoint-rooted Monte Carlo replication

### 13.1 Common initial conditions via checkpointing

To attribute differences in outcome to an experimental manipulation rather than to differences in initial state, all replicates within an experiment originate from a single, fully specified initial condition. The complete state of a simulation - the packed genomes, all continuous and integer per-individual state variables, the resource fields and the active hazard-type registry, the accumulated demographic statistics, the epoch history, and the PRNG state - can be serialized to disk as a *checkpoint*. A typical protocol evolves a founding population under the ancestral hazard regime until it reaches a demographically stationary, locally adapted state, and saves that state as the common origin for all subsequent experimental replicates.

### 13.2 Re-seeding and independent realizations

A checkpoint restores, among other state, the PRNG. A naive restart would therefore replay a single deterministic future. To generate statistically independent stochastic realizations that share an identical initial condition, each replicate re-initializes the PRNG with a distinct seed immediately after loading the checkpoint, rebinding the generator used by both the engine and the world so that all downstream stochastic events (resource placement, movement, tie-breaking, offspring number, and mutation) diverge from the shared starting state. Only the epochs generated after the origin are retained for a replicate, so that every replicate's recorded trajectory begins at the common initial condition and diverges thereafter, isolating the contribution of demographic and genetic stochasticity.

### 13.3 Experimental arms

An experiment ("study") comprises one or more *arms*, each representing an experimental condition defined as a set of overrides applied to the shared base configuration (for example, the presence or timing of the perturbation, or the value of stress_mutation_rate). A single arm constitutes a one-condition replication study; two arms constitute a controlled A/B contrast (for example, hypermutation versus constant mutation under an identical environmental change); and multiple arms constitute a factorial or dose-response design, such as a series of arms differing only in the value of stress_mutation_rate to characterize the dependence of adaptation on mutation supply under stress.

### 13.4 Deterministic seed allocation and parallel execution

Within a study, replicate seeds are allocated by the deterministic rule s(a, r) = s_0 + 10^4 * a + r, where s_0 is the base seed, a the zero-based arm index, and r the zero-based replicate index. This guarantees non-overlapping seed ranges across arms, exact reproducibility of the entire experiment from the base seed alone, and the ability to extend a study with additional replicates without colliding with existing seeds. Replicates are mutually independent and are executed concurrently across all available processor cores using a process pool sized to the machine's logical core count; because replicates share no mutable state, throughput scales with the number of cores, and the same job specification can be distributed across independent machines and merged post hoc.

## 14. Statistical analysis

For each arm and each recorded observable, replicate trajectories are aligned by epoch index (relative to the common origin) and summarized across replicates. We report the replicate mean, standard deviation, standard error of the mean (SEM = s / sqrt(n)), and a nominal 95% confidence interval computed under a normal approximation (mean +/- 1.96 x SEM); given the modest replicate counts typical of such experiments, we additionally provide non-parametric summaries, namely a percentile bootstrap confidence interval of the mean (default 2000 resamples) and empirical quantile bands (default 10th-90th percentiles). Demographic robustness is summarized by a survival curve giving, at each epoch index, the proportion of replicates that remain non-extinct, together with the overall extinction probability and mean time to extinction. When comparing observables at a chosen epoch (by default the final epoch, or the mean over post-burn-in epochs when a burn-in is specified to exclude the initial transient), between-arm contrasts are quantified by the difference in replicate means, a standardized effect size (Cohen's d using the pooled standard deviation), and a two-sided significance level obtained from a label-permutation test on the replicate values (the number of permutations bounded for tractability); where the SciPy library is available, Welch's unequal-variance t-test is reported additionally. To aid design of subsequent experiments, an approximate per-arm replicate count required to detect the observed standardized effect at 80% power and a two-sided 5% level is reported using a normal-approximation formula. All statistical procedures are computed with fixed PRNG seeds derived from the study seed, so that reported intervals and p-values are themselves reproducible.

## 15. Reproducibility and data availability

Every experiment writes a self-describing output directory nested beneath its origin state. This directory contains the per-replicate epoch-level records in both line-delimited JSON and comma-separated tabular form (with per-arm subtables), the across-replicate arm summaries (means, confidence intervals, and quantile bands per epoch and observable), the between-arm comparison statistics, publication-oriented figures (mean-with-confidence-band trajectories, survival curves, and terminal-value bar charts with error bars), and a machine-readable scientific report together with a human-readable rendering that states, per arm, the survival probability and terminal adaptation summary and, per contrast, the effect size, significance, and qualitative verdict. A manifest records the identity and content hash of the origin state, the complete study specification, the base seed and the explicit list of every replicate seed, the numerical backend, and wall-clock timing, so that any result can be regenerated exactly. Configuration is treated as code: all parameters are stored as structured, version-controllable text, and no experimental parameter is set other than through this configuration.

## 16. Default parameterization

Unless otherwise stated, simulations use the following default parameters (all of which may be overridden per experiment or per arm). Spatial and demographic: grid 80 x 80 cells (toroidal); founding population 80 individuals; hard population ceiling 800. Resources: food input rate 4.0 items/tick with persistence 50 ticks; hazard input rate 0.5 items/tick with persistence 200 ticks; perceptual radius 10 cells. Energetics: basal metabolism 0.001 per tick; weight-speed cost coefficient 0.01; food intake 0.2 (times absorption efficiency); emergency energy threshold 0.10; maximum per-encounter hazard loss expressed as a fraction of the motif. Senescence: onset at age 1000 ticks, maximum age 1800 ticks, linear decline. Reproduction: reproductive-age window [700, 1100] ticks; energy thresholds for one and two offspring at 0.50 and 0.75. Genetics: genome length 2048 bits; baseline per-bit mutation rate 0.01; stress per-bit mutation rate 0.20; coding-restricted mutation. Reporting: epoch length 1000 ticks. Hazard motifs: ancestral type A = (11110000) x 4 and novel type B = (00001111) x 4, each with sixteen dangerous, mutually disjoint bit positions. Experiments reported here may substitute a larger lattice and correspondingly rescaled resource inputs; such deviations are stated explicitly and recorded in the run manifest.

## 17. Computational environment

Simulations were implemented in Python 3.12 using NumPy for array computation and Numba for just-in-time compilation of the numerical kernels; an optional CUDA backend is supported but was not used for the reproducibility-critical analyses reported here. Interactive visualization and control are provided by separate front-ends that do not participate in the numerical update, guaranteeing identical results across headless and interactive execution. Batch experiments were executed on a multi-core CPU using a process pool sized to the available logical cores. All reported quantities were computed by the analysis pipeline described in Section 14 directly from the recorded per-replicate outputs.
